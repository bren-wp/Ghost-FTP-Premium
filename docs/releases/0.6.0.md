# Ghost FTP 0.6.0 — Native

Released: pending release gates

**More Than Transfer. Total Control.**

0.6.0 continues the existing React + TypeScript + Tauri + Rust Ghost FTP desktop source. It is a production-fidelity and stability release candidate; it is not FINAL.

## 0.6.0 focus

- Harden native menu popovers so they float above the Quick Connect/header layers and never reflow the application shell.
- Keep File/Edit/View/Transfer/Server/Bookmarks/Tools/Help keyboard-accessible with Escape, arrow-key and focus handling.
- Stabilize the New Connection reference envelope at approximately 752×628 while remaining viewport-safe.
- Remove scale/entrance transforms from critical production surfaces that can cause WebView2/GTK raster jitter during rapid interaction.
- Keep standalone About, Preferences, Site Manager and Transfer Center views isolated from the underlying File Manager chrome.
- Keep notification permission explicit: first-run/background events never trigger an unsolicited OS permission prompt.
- Keep official web links out of new Ghost FTP WebView windows; external navigation is delegated to the operating system.
- Preserve real FTP, explicit FTPS and SFTP protocol paths and the binary FTP/FTPS transfer regression fix.
- Keep production installs free of seeded demo servers, fake transfers, fake progress and fake Connected state.

## Protocol acceptance

The current 0.6.0 protocol workflow exercises real FTP, explicit FTPS and SFTP round trips. A release is allowed only after the current-main quality and protocol gates are both successful.

Implicit FTPS is not advertised.

## Transfer Center

- Transfer lists, progress, speed, ETA and bandwidth data come from the native transfer store.
- Pause/Resume/Cancel/Retry controls are disabled when the selected transfer state does not permit the action.
- Persistent scheduling is not implemented and is not simulated; the UI states this explicitly.

## File Properties

- General and Checksums tabs use real backend capabilities.
- SHA-256 is calculated only when the active backend exposes checksum support.
- chmod and recursive chmod are used only when supported.
- Duplicate/Open Containing Folder actions remain disabled when unavailable.

## Privacy and security

- No analytics or telemetry by default.
- Desktop notifications default off and request OS permission only from an explicit user enable action.
- Tauri updater signature verification remains configured; do not claim signed updater artifacts unless CI signing material is actually present.
- Credentials and private-key passphrases must not be logged.
